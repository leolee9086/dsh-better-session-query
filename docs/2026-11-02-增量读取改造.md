# 2026-11-02 索引改造：从"整份读"改成"按帧续读"

## 为什么改

host 进程反复以 V8 OOM 崩溃（`3221226505` / `134`，日志里是 `FATAL ERROR: MarkCompactCollector ... JavaScript heap out of memory`）。
根因不是 SQLite，也不是系统内存：是索引器走 `ctx.sessionQuery.readSession`，把整份会话日志 load + replay + structuredClone 三次。
`session-926f8ec0` 那份日志压缩后 164MB、24.4 万事件，一次读取就把 4GB 堆打满。

崩溃前的证据（`~/.dsh/logs/session-blocks.log`）：每轮 reconcile 都打出
`慢会话 session-926f8ec0:21585ms(244130 事件; ... 正文 19559ms ...)`，也就是 30 秒一轮、每轮全量重读。

## 改了什么

### rebec（D:\dev\rebec）

`src/session.rs` 新增 `scan(path, from_offset, limit)`：

- 按 zstd 帧结构逐帧切分（不靠找魔数，避免载荷里的假魔数）；
- 每次只读到凑够 limit 条事件为止，读过的字节从缓冲区丢弃；
- 返回 `{ header, events, next_offset, done, torn }`，next_offset 一定落在帧边界；
- 窗口只在帧边界收口，避免"读到一半停下"导致下次漏事件。

`src/napi_api.rs` 导出 `sessionScanLog(path, fromOffset, limit)`（JSON 文本）。

新增 `package.json` + `index.cjs`，让它能作为普通 npm 包被依赖（原先只有本地 `rebec.node`）。

### 插件（D:\dev\dsh-better-session-query）

| 文件 | 改动 |
|---|---|
| `lib/surface.js`（新） | 增量 surface 折叠。维护 seq 序列，处理 `surfaceOp: append / replace`，挤出表层的 seq 回传调用方 |
| `lib/log-source.js`（新） | 定位 `~/.dsh/sessions/*/<id>/session.v4.jsonl.zstd`（TTL 缓存）+ 调 rebec 分批读 |
| `lib/store.js` | `indexed_sessions` 加 `log_path`/`log_offset`/`surface_nodes` 三列；新增 `appendBlocks()`（只插新块、把被挤出的旧块改成 log-only、带断点去重） |
| `lib/blocks.js` | 新增 `buildEventBlocks(event, surface, options)`，单事件抽块 |
| `lib/indexer.js` | `planSession` 改成看文件长度（不读日志）；`writeSession` 改成按窗口读 + 边读边写；`reconcileOne` 同步改参数；新增 `logReader` 注入点 |

## 最终状态（测试全部改完之后）

21 个测试文件、178 项通过。唯一仍失败的是 memory-vectors（3 项，spawn EPERM，沙箱禁止子进程，与本次改动无关）。

### 实现层面被测试逼出来的两个修正

1. **revision 必须带修改时间**。最初写成 String(size)，只看长度：日志原地重写（compaction、修复）时长度可能不变，
   于是这一轮被判成 unchanged，整份新内容被静默跳过。现在 revision = 字节数:修改时间。
2. **只有能证明是纯追加才走增量**。判据是"上次记下的长度正好等于已读到的位置"且文件没变短；
   否则（截断、原地重写、长度对不上）一律当改写，删掉旧块从零重建。

### 测试是怎么改的（区分"实现变了"和"测试过时"）

- indexer / incremental：断言从"读了几次 listEvents / readSession"换成"读了几次 batch / stat"，因为读取路径本身就是被换掉的东西。
- async：并发闸门原来挂在 listEvents 上，新实现不调它，闸门永远不触发。改挂 readSessionBatch 之后，单飞、进度、取消、后台四条才真正被测到。
- title / workspace / logfile / plugin：这几处不是逻辑问题，是接缝没接上——它们都走 apply()，而 apply 内部的 createIndexer 拿不到测试的假会话，
  跑去读真实文件了。现在 apply 的 config 支持注入 logReader（生产不传，走 log-source）。
- plugin 的方法清单补上 readRawBlocks：它本来就在服务上，是测试漏列，不是新增。
- plugin 的修订格式断言随实现一起改（因为实现本身被修正成 长度:时间），不是为了让测试变绿而放宽。

### 可移植性

- surface-oracle.mjs 通过 DSH_HARNESS_SURFACE 环境变量找 harness 源码树，找不到就 SKIP（别人机器上没有那份源码）。
- session-scan.mjs 不再钉死具体会话 id，自动从本机 logs 里挑小/大两份真实日志；没有日志就 SKIP。
